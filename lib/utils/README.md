# lib/utils —— 无业务语义的工具函数

| 文件 | 导出 | 作用 |
| --- | --- | --- |
| [`index.ts`](./index.ts) | `cn` 等 | 与产品逻辑无关的通用小工具 |

## 放进这里的标准

一句话：**换个项目还能不能原样用？**

- 能 → 放这里（`cn` 合并 Tailwind 类名、日期格式化、字符串截断…）
- 不能 → 放对应领域目录（`lib/services/`、`lib/ai/`、`lib/parsing/`…）

## 为什么是 `index.ts` 而不是 `utils.ts`

原先是单文件 `lib/utils.ts`，与 12 个功能目录平铺在 `lib/` 根下，看不出归属。
改成 `lib/utils/index.ts` 后有两个好处：

1. 目录名即语义，`lib/` 根下只剩目录，不再有散落文件
2. 以后工具变多（比如再拆出 `date.ts`、`string.ts`）可以就地扩展，**调用方不用改 import**——
   `@/lib/utils` 依然解析到 `index.ts`

## 约束

- 这里**不允许**出现任何与业务有关的概念（不能出现「面试」「简历」「报告」这类词）
- 不允许引入 `db`、`lib/ai`、React —— 保持零依赖，任何层都能安全引用
- 有副作用的函数（读文件、发请求）不算工具函数，不要放这里
