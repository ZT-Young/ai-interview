# docs/product —— 产品侧文档

回答「**做什么、给谁做、为什么做、怎么衡量做得对不对**」。这里不写实现细节，实现见
[../engineering/](../engineering/)。

| 文件 | 作用 | 什么情况下要改它 |
| --- | --- | --- |
| [PRD.md](./PRD.md) | 产品需求文档。产品定位、三类用户画像、10 步核心流程、页面清单、功能优先级 | 新增/删减功能、调整流程步骤、改动用户画像 |
| [METRICS.md](./METRICS.md) | 指标与埋点设计。5 个埋点事件定义，完面率 / 报告打开率 / 付费率 / 付费意愿的 SQL 口径，隐私合规前置要求 | 加埋点、改指标口径、调整数据看板 |
| [ITERATION_PLAN.md](./ITERATION_PLAN.md) | 迭代计划。V1 内测 → V1.1 分三批的优先级，含内测执行清单与本文件的更新规则 | 一个批次完成或优先级变化时 |
| [BETA_FEEDBACK.md](./BETA_FEEDBACK.md) | 内测反馈问卷。7 个部分共 26 题，附投放方式与回收处理纪律 | 内测前定稿、每轮内测后按反馈修订 |

## 读法建议

1. 先读 [PRD.md](./PRD.md) §1–§3，建立「这是什么产品、谁在用、走哪 10 步」的整体印象。
2. 再看 [METRICS.md](./METRICS.md) §3，理解这个产品当前最关心的三个数字。
3. 想知道下一步做什么，直接看 [ITERATION_PLAN.md](./ITERATION_PLAN.md) §1 优先级总览。

## 注意

- 这些是**产品决策**文档，不代表已实现的代码状态。实际实现进度以
  [../../README.md](../../README.md) 的「当前进度」表为准。
- 涉及产品范围的硬约束（例如 V1 明确不做的功能清单）写在 [../../AGENTS.md](../../AGENTS.md) §3，
  改产品范围前必须先确认那一节。
