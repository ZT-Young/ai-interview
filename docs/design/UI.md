## 3. 状态设计（全站统一）

每个数据页面都必须处理四类状态，**不允许只做成功态**。

| 状态 | 触发 | 表现 | 可执行动作 |
|---|---|---|---|
| **加载中** | 服务端渲染中 / 客户端请求中 | 骨架屏（优先）或「加载中…」文本 | 禁用会重复触发的按钮 |
| **空** | 列表为空 / 尚未生成 | 说明文案 + **明确的下一步入口**（不是空白页） | 引导动作按钮 |
| **错误** | 401 / 403 / 404 / 422 / 5xx / 网络失败 | `Alert` 展示**可读中文**，不回显供应商原始报错 | 重试 / 返回上一页 |
| **断线** | `navigator.onLine === false` 或请求失败 | 顶部横幅提示，离线时禁用提交 | 恢复后自动重连 |

**错误文案约定**（与后端 `ApiError` code 对齐）

| code | HTTP | 用户可见文案示例 |
|---|---|---|
| `unauthorized` | 401 | 登录已失效，请重新登录 |
| `not_found` | 404 | 内容不存在或无权访问 |
| `validation_error` | 422 | 该会话还没有面试计划，请先生成计划 |
| `service_unavailable` | 503 | 服务暂时不可用，请稍后重试 |
| `upstream_error` | 502 | 生成结果异常，请重试 |
| `internal_error` | 500 | 服务器内部错误 |

**空状态示例**

| 页面 | 空状态文案 | 入口 |
|---|---|---|
| `/resumes` | 还没有简历 | 「上传第一份简历」 |
| `/jd` | 还没有岗位 JD | 「添加第一个 JD」 |
| `/sessions` | 还没有面试会话 | 「去准备简历」/「去准备岗位 JD」 |
| `/sessions/[id]`（无计划） | 还没有面试计划 | 「生成面试计划」 |
| 面试房间（无题目） | 暂无可回答的问题 | 「返回面试计划」 |
| 面试房间（已结束） | 面试已结束 | 「返回面试计划」 |

## 4. 面试房间页 `/sessions/[id]/interview`

### 4.1 布局（移动优先，单列）

```
┌─────────────────────────────────────┐
│ ← 返回计划        进度 3/8    [计时] │  ← 顶部条（sticky）
├─────────────────────────────────────┤
│ [断线横幅：网络已断开，正在重连…]    │  ← 仅离线/失败时出现
├─────────────────────────────────────┤
│  (AI)  ┌──────────────────────────┐ │
│  头像  │ 请介绍一次性能优化经历…  │ │  ← AI 气泡（左）
│        └──────────────────────────┘ │
│        [来源 JD+简历] [维度 项目深度]│
│        [追问 1/2]                    │
│                                      │
│              ┌────────────────────┐ │
│              │ 我负责了评分服务…  │ │  ← 用户气泡（右）
│              └────────────────────┘ │
├─────────────────────────────────────┤
│ ┌─────────────────────────────────┐ │
│ │ 输入回答…                        │ │  ← 输入区（多行自适应）
│ └─────────────────────────────────┘ │
│ [🎤 按住说话] [提示] [跳过] [发送]   │  ← 底部操作栏（安全区）
│                        [结束面试]    │
└─────────────────────────────────────┘
```

### 4.2 元素规格

| 元素 | 规格 |
|---|---|
| **AI 面试官头像** | 圆形占位头像 + 「AI 面试官」标签；纯装饰不依赖图片资源，`aria-hidden` |
| **文字气泡** | AI 左对齐（`bg-muted`）、用户右对齐（`bg-primary text-primary-foreground`）、系统居中（无气泡，小字灰字）；气泡内 `whitespace-pre-wrap` 保留换行；单条最大宽度 `85%` |
| **当前问题** | 展示于 AI 气泡内，字号大于普通消息（`text-base`/`text-lg`），行高放宽 |
| **计时** | 本题计时，格式 `mm:ss`；从题目出现开始计时，提交/跳过时停止并把秒数作为 `durationMs` 回传。**不强制限时**（超时不自动提交） |
| **进度** | `进度 {answered}/{total} 道主问题`；追问不计入主问题进度 |
| **文字输入框** | 多行、自动增高（上限约 6 行）、`Enter` 换行、`Ctrl/Cmd + Enter` 提交、`aria-label="你的回答"` |
| **语音按钮** | 按住说话（详见 §4.3）；录音中显示时长与波形/红点，松开即上传 |
| **跳过** | 二次确认（避免误触）；不写回答，直接推进 |
| **请求提示** | 展示 AI 提示气泡，**停留当前题**；提示不产生回答 |
| **结束面试** | 二次确认；结束后进入「已结束」状态，展示完成度 |
| **断线提示** | 见 §4.5 |

### 4.3 按住说话（语音输入）

**交互**

1. `pointerdown` 开始录音（同时请求麦克风权限）→ 按钮进入录音态，显示已录时长
2. 指针移出按钮范围一定距离视为「取消」→ 松手丢弃，不上传
3. `pointerup` 停止录音 → 上传音频 → 服务端转写 → 转写文本**填入输入框**（不自动提交，允许用户修改）
4. 权限被拒 → 提示「未获得麦克风权限，请在浏览器设置中允许后重试」，并引导手动输入
5. 录音失败/转写失败 → 保留录音结果提示重试

**技术约束**

- 使用 `MediaRecorder`（`audio/webm;codecs=opus`，Safari 回退 `audio/mp4`）
- 触摸设备需 `touch-action: none` 与 `user-select: none`，并阻止长按选中
- 需要 HTTPS 或 `localhost`（浏览器安全上下文要求）
- **音频只上传到本站服务端**，ASR 调用在服务端完成 —— **前端不得持有任何 API Key**（AGENTS.md §8、§7 C3）

**ASR 未接入时的行为**（当前状态）

- 录音与上传链路完整实现
- 服务端返回「语音识别暂不可用，请手动输入」→ 前端以提示条展示，**不伪造转写文字**
- 供应商确定后只需替换 `lib/asr/` 的实现

### 4.4 与编排状态机的对应（见 ARCHITECTURE.md §3.6）

| UI 表现 | `phase` |
|---|---|
| 展示题目 | `WAITING_ANSWER`（题目已抛出） |
| 提交后出现追问气泡 | `FOLLOW_UP` → 回到 `WAITING_ANSWER` |
| 提交后出现新主问题 | `NEXT_QUESTION` → 回到 `WAITING_ANSWER` |
| 显示「面试已结束」 | `FINISHED` |
| 展示「尚未生成计划，请先返回计划页」 | 服务端返回 422 |

**不变量**：任何时刻 UI 只展示**一个**待回答的问题（一次只问一个问题）。

### 4.5 断线重连

| 场景 | 表现 | 恢复行为 |
|---|---|---|
| `offline` 事件 | 顶部横幅「网络已断开，恢复后将自动同步」 | 监听 `online` 事件 |
| 提交请求失败（网络类） | 错误提示 + 「重试」按钮；**输入内容不清空** | 点击重试重发 |
| 恢复在线 | 横幅变为「已恢复连接」并在 2s 后消失 | 自动 `GET /api/sessions/:id/next` 拉取当前题 |
| 页面刷新 | 无特殊提示 | 服务端由 `currentQuestionId` + `getNextQuestion` 恢复进度 |

```
│   + 六维数值列表（文字，供无障碍）    │
├─────────────────────────────────────┤
│ 总评（summary）                       │
├─────────────────────────────────────┤

├─────────────────────────────────────┤
│ 待改进 issues            [付费遮罩]   │
├─────────────────────────────────────┤
│ 参考回答 referenceAnswers [付费遮罩]  │
├─────────────────────────────────────┤
│ 简历风险点 resumeRisks    [付费遮罩]  │
├─────────────────────────────────────┤
│ 下一步训练建议            [付费遮罩]  │  ← §5.4
├─────────────────────────────────────┤
│ 逐题反馈（折叠，默认收起） [付费遮罩]  │  ← §5.5
└─────────────────────────────────────┘
```

### 5.2 总分与岗位匹配度

| 指标 | 来源 | 说明 |
|---|---|---|
| **总分** 0–100 | `reports.total_score` | 六维等权折算，可回溯到逐题评分 |
| **岗位匹配度** 0–100 | `interview_sessions.match_analysis.match_score` | **面试前的静态匹配程度**，用于定位准备重点 |

> **必须区分**（见 AI_PROMPTS.md §3.3）：总分来自**实际回答表现**，匹配度来自**简历与 JD 的静态比对**。
> 两者不可互相换算，也**不得**合并成一个数字。
> 匹配度旁必须标注「匹配程度，仅供参考，不代表任何录用判断」（合规 C5）。

### 5.3 六维雷达图（自绘 SVG）

| 项 | 约定 |
|---|---|
| 数据 | 六维各 0–5（`reports.dimension_scores`），固定顺序：岗位匹配→专业能力→项目深度→逻辑表达→沟通表达→动机稳定性 |
| 实现 | **自绘 SVG**（`components/features/report/dimension-radar.tsx`）：不引入图表库，可服务端渲染，无客户端 JS 成本 |
| 尺寸 | `viewBox` 固定比例 + `width="100%"`，容器 `aspect-square` 上限 `max-w-sm` 居中 → 移动端不抖动、不横向溢出 |
| 刻度 | 三层网格环（1/3/5 分）+ 六条轴线 + 顶点数值标注 |
| 无障碍 | 图表标 `role="img"` 与 `aria-label`；**同时渲染六维数值文字列表**，颜色不是唯一信息载体 |
| 空态 | 全部为 0 时仍渲染图形（避免布局塌陷），并提示「尚无评分」 |

### 5.4 下一步训练建议

- 基础来源：`reports.next_steps`（付费解锁）
- **增强**：服务端对**低分维度（< 3）**自动生成针对性建议并置顶（`lib/services/report-service.ts`），
  使用户在未解锁时也能看到**免费的基础建议**（至少 1 条），避免报告页出现「什么都没有」的免费体验。

### 5.5 逐题反馈（长页性能）

| 措施 | 说明 |
|---|---|
| 默认折叠 | 逐题反馈包在 `<details>` 内，**不展开则不渲染重型内容** |
| 虚拟化 | 题目数 ≤ 12，无需虚拟列表；但每题独立折叠，避免一次性展开全部 |
| 长文本 | 回答与反馈用 `whitespace-pre-wrap` + `max-h` + 展开按钮，避免单条撑爆页面 |
| 渲染隔离 | `dimension-radar` 等纯展示组件不标记 `'use client'`，保持服务端渲染 |

#### 每题内部的信息顺序（有意如此）

```
你的回答  →  评分依据（回答原文）  →  参考答案
  诊断        证据支撑                示范
```

**参考答案放最后**：先让用户看自己的回答与评分依据（反思），再看示范。
若放在最前，用户会直接跳到答案而跳过反思，训练效果打折。

#### 参考答案的展示规则（`data-testid="reference-answer"`）

参考答案由模型基于候选人**真实简历经历**生成，凡无法确定的具体信息
（数字、指标、时间、规模、技术细节）都被要求写成 `【待补充：…】` 占位符。

| 规则 | 原因 |
|---|---|
| 占位符用 `<mark>` **高亮** | 若整段同一样式，用户会连 `【待补充：…】` 一起背诵，或在面试中报出不属于自己的数字 |
| 区块顶部给一句警示 | 明确「这是示范，用于学习结构与措辞，请换成你的真实数据」 |
| 无参考答案时**不渲染该区块** | 历史数据与模型未产出该字段的情况需兼容，且不显示空壳 |

> ⚠️ **合规边界**：参考答案**只能**使用简历与本次回答中出现的真实经历。
> 模型侧约束见 [AI_PROMPTS.md §6.2](./AI_PROMPTS.md)；前端不得对参考答案做
> 「补齐数字」之类的自动润色，那会把占位提示变成编造。

### 5.6 免费 / 付费边界

| 免费可见 | 付费解锁 |
|---|---|
| 总分、岗位匹配度、六维雷达与数值、总评、优势、**基础训练建议** | 待改进、参考回答、简历风险点、完整训练建议、逐题反馈与证据（含**逐题参考答案**） |

**未解锁时服务端不返回付费字段内容**，只返回 `lockedSections`（被锁字段名），UI 渲染遮罩与「前往会员页」入口。
逐题参考答案属于逐题反馈的一部分，因此**同样受付费边界约束**。

## 8. 管理后台 `/admin`

> **访问控制**：`users.is_admin = true` 才能访问。非管理员访问任何 `/admin` 页面或 API
> **一律返回 404**（与全项目一致：不泄露资源/入口是否存在）。
> 管理员身份**只能手动改库提升**，系统不提供任何自我提权接口。

### 8.1 路由与页面

| 路由 | 内容 |
|---|---|
| `/admin` | 概览：用户数、会话数、报告数、订单数、近期 AI 错误数 |
| `/admin/users` | 用户列表（邮箱、昵称、等级、剩余次数、注册时间、是否管理员）+ 调整免费次数 |
| `/admin/sessions` | 面试会话列表（状态、编排阶段、题量、是否已出报告） |
| `/admin/orders` | 订单列表（金额、状态、解锁类型、渠道订单号**脱敏**） |
| `/admin/logs` | AI 调用日志与错误日志（同表，按 `status` 区分） |

### 8.2 敏感数据边界（硬要求）

> **不暴露用户简历原文给无关人员。**

| 数据 | 默认 | 开启后 |
|---|---|---|
| `resumes.raw_text` | **不返回、不渲染** | 需 `ADMIN_VIEW_RESUME_CONTENT=true` |
| `resumes.parsed_data` | **不返回、不渲染** | 同上 |
| 简历文件名 / 大小 / 解析状态 | 可见 | 可见 |
| 用户密码哈希、会话令牌 | **永不返回** | 永不返回 |
| AI 日志中的提示词与响应正文 | **不记录、不返回**（只记元数据） | 同左 |

**查看简历原文的每次访问都写入审计日志**（`action: 'admin.resume_content_viewed'`），
包含操作者、目标用户、目标简历与时间。

### 8.3 布局与移动端

- 独立布局：`app/admin/layout.tsx`，**不复用 `(app)` 的导航**（避免普通用户导航中出现后台入口）
- 服务端守卫：`requireAdmin()` → 非管理员 `notFound()`
- 表格在窄屏横向滚动（`overflow-x-auto`）；后台以桌面运营场景为主，不做移动端专用折叠
- 所有列表默认 50 条上限，并显示总数

### 8.4 审计日志（只增不改）

| 操作 | `action` | 记录内容 |
|---|---|---|
| 调整免费次数 | `admin.credits_adjusted` | 目标用户、调整前后值、增量、原因 |
| 查看简历原文 | `admin.resume_content_viewed` | 目标用户、目标简历 |
| 查看用户详情 | `admin.user_viewed` | 目标用户 |

**不提供任何删除或修改审计日志的接口**（AGENTS.md §7 C6）。
