# B 端：面试官侧（Interviewer Side）

> 上位依据：[AGENTS.md](../../AGENTS.md) §7（合规红线）；字段与枚举单一真源 [DATA_MODEL.md](../engineering/DATA_MODEL.md)；页面规格沿用 [UI.md](./UI.md) 的约定（四态、错误文案、无障碍）。
>
> 本文档是 B 端三个场景的**唯一规格**。B 端新增 anything 前先改这里。

---

## 1. 为什么单独写一份文档

B 端不是「多加几个页面」，而是**把 AI 输出的使用者从本人换成第三方**。这一步跨过去，
AI 结果就从「自我提升参考」变成「他人评价依据」，直接触碰 AGENTS.md §7 C5：

> **C5 决策边界**：不得仅凭 AI 自动拒绝候选人——AI 结果只作参考与提升建议。

因此本项目的 B 端有一条**不可协商的边界**：

> **面试官侧永远不产出、不展示、不暗示任何录用相关结论。**
> 没有「通过 / 不通过」「适合 / 不适合」「建议录用」「淘汰」「候选人排名」「录取概率」。
> AI 输出只允许是：客观记录、结构化纪要、提问质量反馈、候选人**自己选择分享**的练习结果。

这条边界同时是法律要求：个保法第 24 条规定，对个人权益有重大影响的自动化决策，
个人有权要求说明并**有权拒绝仅通过自动化决策的方式作出决定**。招聘筛选正属此类。

**守住它的方式不是写注释，是数据模型与接口层不留那条路**：
分享出去的报告里没有任何字段能表达「录用结论」，不是靠前端藏起来。

## 2. 三个场景

| 编号 | 场景 | 一句话 | 是否接触候选人数据 |
|---|---|---|---|
| A | **授权查看** | 候选人主动把自己的练习报告分享给指定面试官，带有效期、可撤销、有查看记录 | 是（**须候选人主动授权**） |
| B | **AI 面试助手** | 真实面试中的录音转写与结构化纪要，帮面试官记住而非替他判断 | 由面试官录入，不自动同步候选人account |
| C | **反向练习** | AI 扮演求职者，让面试官练提问、追问与节奏控制 | 否 |

三者的数据互不复用：A 是「分享令牌」，B 是「面试官自己的记录」，C 是「练习会话」。
**刻意不做第四件事**：pipeline / 候选人排名 / ATS —— 那是本文档 §1 边界的正面突破。

## 3. 身份模型（`user_role`）

`users.role`（枚举 `user_role`）：

| 值 | 含义 | 默认 |
|---|---|---|
| `candidate` | 求职者（C 端现有用法） | ✅ 新用户默认 |
| `interviewer` | 面试官 / HR / 招聘方 | 在设置里自主切换 |

**关键取舍**：一个自然人可能同时是求职者和面试官。完整做法是
`organizations + memberships` 的多身份租户模型，但那要重写
`interview_sessions` / `resumes` / `job_jds` 三张表的归属列与所有查询，
收益（企业多席位、组织级数据隔离）在 V1 拿不到。

因此本期采用**单值角色 + 自助切换**：`role` 一列决定「当前身份」，
数据在两个身份下都保留，切换身份不丢数据。

> 已知代价：无法「同时拥有两种身份的权限」。用户需要看另一侧的界面时得切换一次。
> 这在 V1 可接受；一旦出现真实企业客户，必须升级为组织租户模型
> （届时 `role` 迁成 `memberships`，本文 §3 整体改写）。

`role` 与 `is_admin` **正交**：`is_admin` 是管理后台权限，`role` 是产品身份。
一个人可以既是求职者又是后台管理员。

## 4. 场景 A：授权查看

### 4.1 两种授权方式

| 方式 | 触发方 | 载体 | 适用 |
|---|---|---|---|
| **链接**（`kind='link'`） | 候选人 | 一次性 URL + 可选访问码 | 主动投递：「这是我的练习报告」 |
| **邀请**（`kind='invite'`） | 面试官 | 面试官填候选人的邮箱/手机号/用户名发起请求 | 主动猎聘：「方便发我看看吗」 |

**两种方式都必须留下候选人的明确同意动作**：

- 链接：候选人**亲手创建**令牌，即构成授权；可随时撤销
- 邀请：候选人在站内看到待确认请求，**接受后**才生成可读令牌；可拒绝、可接受后再撤销

> 为什么不用「后台自动开放」：那等于系统替候选人做同意决定，违反 AGENTS.md §7 C1。

#### 邀请为什么不带 `session_id`

B 端 V1 **没有岗位 / 候选人列表**（这是 §3 租户取舍的直接后果），
面试官根本无从知道候选人练过哪几场。所以邀请只能携带「候选人标识 + 附言」发起，
由候选人在接受时**自选要分享哪一场**，此刻才写入 `report_shares.session_id`。

这是流程被数据模型逼成两步，而不是可以随手优化掉的麻烦：
硬要让面试官指定报告，就得先做「候选人列表」——那正是本期明确不做的租户能力。
悬空记录由 CHECK（`status <> 'active' OR session_id IS NOT NULL`）堵死。

### 4.2 `report_shares` 表（字段级定义见 DATA_MODEL §3.14）

核心字段：

| 字段 | 作用 |
|---|---|
| `owner_id` | 候选人（数据主人） |
| `session_id` | 被分享的那一场面试 |
| `kind` | `link` / `invite` |
| `token_hash` | 链接模式：URL 里的令牌**只存哈希**（与会话令牌同原则） |
| `invitee_user_id` / `invitee_identifier` | 邀请模式：接受者 / 发起时填的标识 |
| `status` | `pending`（待候选人确认）→ `active` / `declined` / `revoked` |
| `visibility` | `summary`（总分 + 六维 + 优势 + 总评）或 `full`（含逐题反馈与参考回答）——**由候选人选** |
| `expires_at` / `revoked_at` | 有效期与撤销（任一命中即不可访问） |
| `access_code_hash` | 可选二次校验，防止链接被转发后裸奔 |
| `view_count` / `last_viewed_at` | 候选人能看见「谁在什么时候看过」的次数 |

### 4.3 访问规则

1. 未过期、未撤销、且 `active` 才可访问
2. 链接模式：持有 token 原文 + 访问码（若设了）
3. 邀请模式：还必须 `invitee_user_id` 等于当前登录用户 —— 链接转发给别人也读不到
4. **每次访问写审计日志**（`report.share_viewed`，含分享 ID 与访问者），并累加 `view_count`
5. `visibility='summary'` 时，付费字段的内容**不出现在响应里**（复用 `getReportBySession` 的裁剪口径，
   与免费/付费边界同一套实现，不另写一个 potion）

### 4.4 页面

| 路由 | 访问者 | 内容 |
|---|---|---|
| `/interviewer/shares` | 面试官（role=interviewer） | 「被分享给我的报告」列表 + 我发出的邀请 |
| `/share/[token]` | 任意（无需登录） | 只读报告页 |
| 报告页 `/sessions/[id]/report` | 候选人 | 新增「分享给面试官」卡片：创建链接 / 查看已分享 / 撤销 / 待确认邀请 |

`/share/[token]` 顶部必须同时展示两个标识（C4）：

- 「本报告由 AI 生成，仅供练习参考」
- 「本内容由候选人主动分享给你，**不构成录用建议**」

页面**禁止**出现的元素：总排名、相似度排序、录取建议、任何与「录用」相关的按钮。

## 5. 场景 B：AI 面试助手（记录与纪要）

面试官在真实面试中用它做**记录**，不是做判断。

- 录入：岗位标题、候选人标识（面试官自己填，如「候选人 A」）、音频或转写文本
- 产出：**结构化纪要**（提到了什么经历 / 待核实的点 / 面试官自己漏问的维度）
- **不产出**任何分数、评级、结论

> 「漏问了什么」这类反馈是**对面试官提问行为的反馈**，对象是面试官本人，
> 因此不违反 C5 —— 红线约束的是「对被面试者下自动化结论」。

数据：`interview_records`（详见 DATA_MODEL §3.15）。
录音转写复用 `lib/asr` 端口（当前未接供应商，返回 503 而非伪造文字）。

## 6. 场景 C：面试官反向练习

镜像形态：AI 扮演候选人，面试官练习**提问**。

- 面试官开一场反向练习 → AI 生成一个虚拟候选人（简历 + 背景，明确标注虚构）
- 面试官提问 → AI 按候选人设定作答（含「答不上来 / 答得含糊」，考验追问）
- 结束后给**面试官**的反馈：问题是否开放、是否覆盖 STAR、有无引导性提问、追问是否抓住模糊点

这套 Prompt 与 C 端的 `interview` / `follow_up` prompt 完全不同方向，
放在 `lib/ai/prompts/reverse-*`，版本号独立（改 prompt 必须递增，见 README 已知事项 27）。
